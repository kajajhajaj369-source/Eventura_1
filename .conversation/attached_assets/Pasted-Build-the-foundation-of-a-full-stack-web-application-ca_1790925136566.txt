Build the foundation of a full-stack web application called:

EVENTURA

==================================================
PHASE 1 — FOUNDATION
==================================================

Build the technical foundation for EVENTURA.

The application should be structured as a real full-stack application, not a static prototype.

Use a modern stack appropriate for a production-style web application.

Prefer:

- React / Next.js
- TypeScript
- Tailwind CSS
- PostgreSQL-compatible database
- Secure authentication
- Role-Based Access Control
- Reusable components
- Responsive design

Use Replit's available database/backend capabilities where practical.

==================================================
1. PRODUCT IDENTITY
==================================================

Application name:

EVENTURA

Tagline:

One Platform. Every Campus Event.

Description:

A centralized College Event & Club Management Platform connecting:

- College Admin
- Clubs
- Organizers
- Students
- Volunteers

The goal is to provide one source of truth throughout the campus-event lifecycle.

2. Club

4. Student

==================================================

Implement:

- Login

- profile information
- created timestamp
- updated timestamp

==================================================
4. ROLE-BASED ACCESS CONTROL
==================================================

Create the RBAC foundation.

At minimum:

ADMIN
- campus-wide access

CLUB
- club-level access

ORGANIZER
- event-level access

STUDENT
- own user data

VOLUNTEER
- assigned event/task data

IMPORTANT SECURITY REQUIREMENT:

Do not rely only on frontend checks.

Structure the backend/database authorization so that unauthorized users cannot simply access another role's data by changing a URL or request.

Keep the permission system centralized and reusable.

==================================================

Create the initial database schema needed for the entire EVENTURA system.

At minimum establish the foundation for:

roles
colleges

volunteer assignments
tasks

Do not overbuild all fields yet.

The important requirement is to establish clean relationships and IDs so later phases can extend the schema without rebuilding the entire database.

Use:

- foreign keys
- timestamps
- appropriate unique constraints
- useful indexes
- status fields

Use UUIDs where appropriate.
